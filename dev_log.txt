2. Core Data Model (Image)

Defined a POD-style Image struct:

struct Image {
    int width;
    int height;
    int channels;
    uint8_t* data;
};


Image memory is:

linear

row-major

interleaved by channels

Chose uint8_t* for GPU friendliness and explicit memory control

3. Memory Ownership Model (Very Important)

Introduced image_utils.hpp/.cpp

Implemented:

create_image(width, height, channels)

free_image(Image&)

Key rule established:

The caller owns image memory.
Processing functions never allocate or free memory.

Learned why:

prevents leaks & double-free

simplifies pipelines

matches CUDA execution model

3. Architectural Correction

Enforced clean separation:

src/image_utils.cpp  → memory + conversion utilities

Moved grayscale logic out of image_utils.cpp

Created:

src/cpu/grayscale_cpu.cpp

4. STEP 5 — CPU Grayscale Conversion (Major Milestone)

Implemented grayscale_cpu(const Image&, Image&)

Design principles followed:

no allocation inside algorithm

caller owns input/output memory

explicit index calculation

deterministic float math

Used standard luminance formula:

gray = 0.299R + 0.587G + 0.114B


Loop structure:

nested for (y, x)

one pixel per iteration

Explicit linear indexing:

rgb_idx  = (y * width + x) * 3
gray_idx = (y * width + x)

5. STEP 5 Test Harness

Updated main.cpp to:

save gray_cpu.png

Verified:

image dimensions unchanged

output visually grayscale

no memory leaks or crashes

6. Conceptual Breakthrough

Clearly understood why CPU and future CUDA results will match:

grayscale is embarrassingly parallel

each pixel is independent

no shared state

no order dependence

Identified this as the ideal first CUDA kernel
